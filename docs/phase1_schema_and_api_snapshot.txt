TABLE 1: CROSS-DOCUMENT CONFLICTS & ARCHITECTURE ALIGNMENT DECISIONS
--------------------------------------------------------------------------------
| Conflict Dimension | Discrepancy Across Documents | Architecture Alignment Decision |
|---|---|---|
| MVP Scope vs. B2B & Extended Features | Lightweight spec limits scope to 9 pages (no coupons, recommendations, or complex refunds); business rules & layout docs cover 17 modules, B2B licensing, financial settlement, ticket transfer, special seats, and Dark Mode. | Align core ERD/3NF schema upfront; deliver code in phases: Phase 1 (Customer Ticketing MVP + Cinema Basic Admin) -> Phase 2 (B2B Distribution + Dashboard + Extended UX). |
| State Machine Granularity | Lightweight spec uses simplified 3-state seats and basic orders; business rules define 4-state seats, 8-state orders, and 4-state payments. | Adopt the strict business-rule enums in backend & database from Day 1; map simplified labels on frontend UI to prevent Phase 2 schema rework. |
| Coupons & After-Sales Rules | Lightweight spec puts coupons in Won't; UI layout mentions applying discounts in steps 8-9; both pre-showtime refund and ticket transfer exist. | Phase 1 supports pre-showtime simulated refund only (no coupons), while reserving `discount_amount` in `orders` for seamless Phase 2 extension. |

TABLE 2: CLOUD INFRASTRUCTURE & KEEP-ALIVE MAPPING (RENDER + UPTIMEROBOT)
--------------------------------------------------------------------------------
| Introduced Component | Role in Three-Tier Architecture | What It Replaces & Rationale |
|---|---|---|
| Render.com (Web Service + Static Site) | Cloud Host for Application Tier (FastAPI Gate) | Does NOT replace FastAPI; hosts FastAPI as the sole API gate between multi-end clients (Flutter + Admin Web) and Supabase PostgreSQL. Admin Web runs on free Render Static Site to preserve the 750-hour monthly Web Service quota. |
| UptimeRobot (5-Minute Ping) | Keep-Alive Trigger & External Lightweight Scheduler | Replaces FastAPI in-process background cleanup scheduler. Keeps Render free tier awake and triggers batch order expiration (`EXPIRED`). Does NOT replace SQL Atomic Lazy Reclamation (primary real-time guard against 5-min blind-spot deadlocks). |

TABLE 3: PHASE 1 DATA MODEL (3NF) - 1.1 IDENTITY & MULTI-CINEMA RBAC DOMAIN
--------------------------------------------------------------------------------
| Table Name | Key Columns & Constraints | Responsibility |
|---|---|---|
| users | id (UUID PK = Supabase sub), email (UNIQUE), full_name, phone, is_active, created_at, updated_at | Business user profile synced via FastAPI Lazy Upsert upon JWT verification. |
| roles | id (PK), code (UNIQUE: CUSTOMER / CINEMA_ADMIN / PLATFORM_ADMIN), name | System role dictionary. |
| user_roles | id (PK), user_id (FK -> users.id), role_id (FK -> roles.id), cinema_id (FK -> cinemas.id, nullable), UNIQUE(user_id, role_id, cinema_id) | RBAC assignment; CINEMA_ADMIN binds cinema_id to enforce strict cinema-level data isolation. |

--------------------------------------------------------------------------------
TABLE 4: PHASE 1 DATA MODEL (3NF) - 1.2 MOVIE, CINEMA & SHOWTIME DOMAIN
--------------------------------------------------------------------------------
| Table Name | Key Columns & Constraints | Responsibility |
|---|---|---|
| movies | id (PK), title, synopsis, duration_minutes, rating, language, poster_url, release_date, status (COMING_SOON / NOW_SHOWING / ARCHIVED) | Movie master catalog. |
| cinemas | id (PK), name, address, city, state, is_active | Cinema branch master record. |
| auditoriums | id (PK), cinema_id (FK -> cinemas.id), name, total_rows, total_cols, UNIQUE(cinema_id, name) | Screening hall within a cinema. |
| seats | id (PK), auditorium_id (FK -> auditoriums.id), row_label, seat_number, seat_zone (STANDARD / VIP), seat_type (STANDARD / TWIN / WHEELCHAIR), UNIQUE(auditorium_id, row_label, seat_number) | Physical auditorium seat layout (seat_type reserved for Phase 2 special seating). |
| showtimes | id (PK), movie_id (FK -> movies.id), auditorium_id (FK -> auditoriums.id), start_time, end_time, base_price, status (SCHEDULED / CANCELLED / COMPLETED) | Scheduled movie screening (Service layer validates non-overlapping hall schedules). |
| showtime_seats | id (PK), showtime_id (FK -> showtimes.id), seat_id (FK -> seats.id), price, status (AVAILABLE / HELD / SOLD / BLOCKED), held_by_order_id (FK -> orders.id, nullable), hold_expires_at, version (optimistic lock), UNIQUE(showtime_id, seat_id) | Anti-overselling core table with snapshotted price, SQL atomic lazy reclamation, and optimistic concurrency control. |

--------------------------------------------------------------------------------
TABLE 5: PHASE 1 DATA MODEL (3NF) - 1.3 ORDER, E-TICKET, PAYMENT & REFUND DOMAIN
--------------------------------------------------------------------------------
| Table Name | Key Columns & Constraints | Responsibility |
|---|---|---|
| orders | id (PK), order_no (UNIQUE), user_id (FK -> users.id), showtime_id (FK -> showtimes.id), status (PENDING_PAYMENT / CONFIRMED / USED / CANCELLED / EXPIRED / REFUND_PENDING / PARTIALLY_REFUNDED / REFUNDED), subtotal_amount, discount_amount (default 0), total_amount, hold_expires_at, idempotency_key (UNIQUE), created_at, updated_at | Customer booking order header with idempotency protection (discount_amount reserved for Phase 2). |
| order_items | id (PK), order_id (FK -> orders.id), showtime_seat_id (FK -> showtime_seats.id), unit_price, UNIQUE(order_id, showtime_seat_id) | Line items linking an order to specific showtime seats. |
| tickets | id (PK), order_id (FK -> orders.id), order_item_id (FK -> order_items.id, UNIQUE), ticket_code (UNIQUE), qr_payload, status (VALID / USED / CANCELLED / REFUNDED), issued_at, used_at | Issued e-ticket and dynamic QR payload. |
| payments | id (PK), order_id (FK -> orders.id), provider (MOCK_PAY), provider_tx_id (UNIQUE), amount, status (PENDING / SUCCEEDED / FAILED / UNKNOWN), idempotency_key (UNIQUE), created_at | Payment attempt ledger supporting multiple attempts per order and simulated gateway callbacks. |
| refunds | id (PK), order_id (FK -> orders.id), payment_id (FK -> payments.id), amount, reason, status (PENDING / SUCCEEDED / FAILED), created_at | Refund transaction record. |

TABLE 7: PHASE 1 RESTFUL API (/api/v1) - A. PUBLIC & CUSTOMER ENDPOINTS (FLUTTER)
--------------------------------------------------------------------------------
| Method & Endpoint | Auth / Role | Core Capability |
|---|---|---|
| GET /api/v1/auth/me | Bearer JWT | Verify Supabase ES256 JWT, execute Lazy Upsert, and return current user profile & roles. |
| GET /api/v1/movies | Public | List NOW_SHOWING and COMING_SOON movies with filtering. |
| GET /api/v1/movies/{id} | Public | Retrieve full movie details and metadata. |
| GET /api/v1/showtimes | Public | Filter bookable showtimes by movie_id, cinema_id, and date. |
| GET /api/v1/showtimes/{id}/seats | Public | Fetch real-time seat map (expired HELD seats dynamically projected as AVAILABLE). |
| POST /api/v1/orders | CUSTOMER | Transactional seat hold & order creation (requires Idempotency-Key header; max 6 seats; 5-min hold). |
| GET /api/v1/orders | CUSTOMER | List authenticated customer's booking history. |
| GET /api/v1/orders/{id} | CUSTOMER | Retrieve order details, hold countdown, and issued e-tickets (tickets + qr_payload). |
| POST /api/v1/orders/{id}/pay | CUSTOMER | Mock Payment Adapter (supports test scenarios: SUCCEEDED, FAILED, TIMEOUT; idempotent ticket issuance). |
| POST /api/v1/orders/{id}/refund | CUSTOMER | Request full simulated refund (>= 60 mins before showtime); atomically releases seats and writes audit log. |
