**为每项核心功能建立一条完整的逻辑链（Business Rule）：**
*痛点 → 解决方案 → UI → 业务规则 → 数据 → 技术实现 → 验收标准。*





**A 部分：消费者痛点分析**

用户想知道电影几点上映	痛点：场次信息分散，难以比较

提供场次筛选		解决方案：统一展示可购场次

设计场次列表与筛选器	UI 实现：场次卡片、时间筛选、票价排序

同步影院真实场次		系统能力：场次数据接口、库存同步

确保用户买到座位		业务规则：库存锁定、订单确认、并发控制







**B 部分：影院运营管理**

后台创建放映场次 *→* 发布 *→* 用户前台查询该场次



**影院后台** （创建电影场次、设置票价、发布排片）

&#x20;      ⇅

**共享业务数据** （电影、场次、座位库存、票价、订单）

&#x20;      ⇅

**用户应用** （查询场次、选座、付款、获取电子票）



*影院运营者与平台管理员不应该默认拥有相同的权限。影院可以管理自己获授权的场次和订单，但不应该随意修改其他影院的资料或查看其他商家的客户交易数据。*







**C 部分：电影工作室、版权方及发行商**

发行合作管理 （管理影片资料、发行商、合作影院、授权区域、有效期限、申请状态、合同记录及报表。）



在 Dashboard 中区分：

\- 曝光次数（Impressions）

\- 影片详情点击次数（Detail Views）

\- 预告片播放次数（Trailer Plays）

\- 场次查看次数（Showtime Views）

\- 购票订单数（Orders）

\- 成交票数（Tickets Sold）

\- 票房金额（Gross Ticket Sales）

\- 平台实际收入（Platform Revenue）





**D 部分：多方共赢的平台生态**

消费者、影院、发行商、电影方、平台 之间形成合作关系



**平台如何同时吸引供给方与需求方**

1\. 消费者希望有足够多的电影、场次和影院。

2\. 影院希望有足够多的潜在观众。

3\. 发行商希望有合适的发行渠道和可衡量的推广效果。

4\. 平台需要双方都愿意持续使用，才有机会形成商业价值。



**UI 规划方面 :**

1. **消费者移动端**：首页、电影详情、影院列表、场次选择、座位图、订单确认、付款结果、电子票、个人订单。
*验收目标：完整演示一次成功购票，以及付款失败和订单取消的处理。*
2. **影院管理后台端**：场次管理、放映厅与座位配置、票价、订单管理、销售 Dashboard。
*验收目标：后台发布的场次能够同步到消费者端，并正确反映库存变化。*
3. **发行商及平台管理后台端**：电影资料、发行方资料、授权范围、影院合作申请、审核记录、推广和商业分析。
*验收目标：可以完整演示一项合作申请，从提交、审核到生效及记录查询。*
* \*\*系统可靠性及完善 ：\*\*权限控制、异常处理、日志、数据验证、响应式 UI、测试及项目文档
*验收目标：证明关键流程不只是视觉演示，而是有一致的业务规则和数据行为。*





* **准备流程：**
1. \*\*角色与权限矩阵（RBAC）：\*\*多个业务角色，因此需要定义每个角色能看什么、改什么、批准什么
2. **核心业务流程与状态机 ：定义订单从创建到完成**的状态变化 (Pending Payment → Confirmed → Used) ; 处理付款失败、超时取消、退款申请和退款完成等分支 ; 授权申请、影院入驻审核和场次发布。
3. **数据模型与系统边界 （ERD）：Movie、Cinema、Auditorium、Showtime、Seat、Order、Ticket、Payment、Refund、DistributionAgreement 等实体之间的关系
*“Seat* <i>座位预订设置独立状态 - AVAILABLE(可以预订) → HELD(暂时锁定，等待付款) → SOLD(已经完成预订)；BLOCKED(预留/维护)</i>”**
“***Order*** *订单状态 - PENDING\_PAYMENT、CONFIRMED、USED，CANCELLED、EXPIRED、REFUND\_PENDING、PARTIALLY\_REFUNDED、REFUNDED*”
“***Payment*** *支付状态 - PENDING、SUCCEEDED、FAILED、UNKNOWN*”
4. **MVP 范围与开发优先级** \*\*：\*\*完成一条端到端购票流程，再实现影院后台和发行合作模块
5. \*\*验收标准 ：\*\*用户能够完成购票；影院能够发布场次；发行商能够提交合作申请；管理员能够审核；Dashboard 能够根据订单数据生成一致的销售指标





* **Data class**

|**业务领域**|**核心实体**|**主要用途**|
|-|-|-|
|账号与权限|User, Role, UserRole|登录、角色分配、访问控制|
|电影资料|Movie, MovieAsset, Genre|电影介绍、海报、预告片及分类|
|影院资料|Cinema, Auditorium, Seat|影院、放映厅、座位配置|
|排片|Showtime, ShowtimeSeat|场次安排、单场座位状态与价格|
|购票|Order, OrderItem, Ticket|订单、购买项目、电子票|
|支付与退款|Payment, Refund|支付尝试、支付结果、退款记录|
|发行合作|Distributor, DistributionAgreement, CinemaPartnership|发行商、授权和影院合作|
|推广分析|Campaign, AnalyticsEvent|推广活动、曝光与用户行为|
|系统治理|AuditLog, Notification|操作审计、订单及合作通知|

细节：

1. Movie 与 Showtime 应分开。电影是一项影片资料，场次则是某个影院在某个时间安排的一次放映。

2\. Seat 与 ShowtimeSeat 应分开。前者描述放映厅的实体座位，后者描述座位在特定场次中的可售状态及价格。

3\. Order 与 Payment 应分开。一个订单可能存在多次支付尝试。

4\. DistributionAgreement 应保存授权范围、有效期限、状态等资料，但不能仅凭数据库记录就认定某方在现实世界中确实拥有合法版权。

5\. 销售报表必须有明确的统计口径，不能将订单金额、实际票房与平台收入混为一谈。
